## 0. 重要结论：9 条 FAIL 的共性

逐张查看 9 张 `FAIL-*.png`（位于 `exp/scratch/clone/pilotdeck-mobile/review/`，属**克隆草稿副本**，非线上 NAS 实例）后，发现它们**不是 9 个独立 bug，而是同一类现象**：

> **每张截图都卡在「What's on the plan today?」新会话欢迎页，从未导航到目标视图**（成果 tab / 画布 / 标注模式 / 目标会话）。

页面本身渲染正常、无报错。这意味着验收自动化（或手动截图）**没有把 UI 驱动到目标状态**——很可能是克隆副本构建陈旧、或截图时机早于导航完成。**线上 NAS 实例用户一直在正常使用（会话能打开、bridge 能连），说明导航功能本身可用**。

因此：这 9 项需要在**真机/浏览器对线上实例**重新跑一遍验收，确认是否仍 FAIL。下表给出每项的功能域、代码落点与预期修复方向。

## 3. 数据清理项（#7）的处理

「清掉验收期间写进正式库的数据」是**运维操作，不是代码 bug**。它会触碰生产数据库，**必须先取得明确授权**再执行，且操作前必须备份。当前不建议在自动化流程里静默执行。待你确认后，我们再在 NAS 上：
1. 备份 `auth.db` / 会话仓库目录；
2. 定位验收时间段写入的测试项目/会话；
3. 经你确认清单后清理。

## 4. 浏览器/真机验证清单（环境到位后逐项过）

在**线上 NAS 实例**打开移动端视图，逐项确认：

- [ ] **会话导航**：打开一个「有成果」的会话 → 是否自动/可切到「成果」tab 并渲染成果？
- [ ] **空态会话**：打开「无成果」的会话 → 「成果」tab 是否给出空白画布（非报错/空白欢迎页）？
- [ ] **手绘**：进入成果 → 切手绘模式 → 在成果上绘制 → 保存 → 重开是否仍在？
- [ ] **空白页手绘**：空白页（无成果）是否也能绘制并保存？
- [ ] **框选标注**：框选区域 → 标注工具栏出现 → 保存按钮是否始终在视口内？保存后是否回到主画面且标注保留？
- [ ] **数据清理**：验收写库的测试数据是否清理（按 §3 流程，需授权）。

把上述任一项的实际表现（截图/控制台报错）发回，即可定位是「导航/状态」还是「持久化/渲染」问题，并据此在上游 UI 落地最小修复（同时新增对应 patch 到 `patches/` 以防上游同步覆盖）。

## 5. 为什么不现在直接改上游 UI

1. NAS 无浏览器/真机，**无法复现也无法验证**任何 UI 改动；
2. 这些文件属 **vendored 上游**，盲改既可能引入回归，又会在上游同步时**被覆盖**（历史上因此出过事故，现由 `patches/` 通道监控）；
3. 9 张截图共性（都停在欢迎页）强烈提示问题在**验收驱动/克隆构建**而非产品本身，盲目改 UI 很可能改错地方。

故本阶段交付「定位 + 清单 + 修复方向」，实修留待验证环境。
