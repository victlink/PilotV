# MCP Streamable HTTP transport relay

Independent Node 22+ TypeScript process. Install with `npm ci`, run `npm test && npm run build`, then `node --env-file=.env dist/main.js` (copy `.env.example` to `.env` and configure it first). Alternatively export the variables and use `npm start` or `npm run dev`.

`MCP_UPSTREAMS` is a JSON map of fixed instance IDs to exact upstream MCP URLs. For example, `{"local":"http://127.0.0.1:9000/mcp"}` exposes `POST`, `GET`, and `DELETE /mcp/local`. `/health` returns gateway process status only; it **does not test upstream availability**. Bind defaults to `127.0.0.1:8765`. `ALLOWED_ORIGINS` is a comma-separated list of browser origins; requests without Origin (non-browser clients) are accepted. Deploy behind authenticated same-origin infrastructure and TLS if exposed beyond loopback; this relay is not an authentication boundary. Forwarded Authorization is never stored or logged; isolate browser users with upstream-issued sessions, but clients without upstream sessions have no isolation guarantee. Never publish it openly without access controls.

The relay streams request/response bytes and SSE without interpreting JSON-RPC methods, preserving tools/resources/prompts/sampling and `MCP-Protocol-Version`/`Last-Event-ID` as transport data. Upstream-issued session IDs are replaced by random downstream tokens bound to an instance and kept only in process memory (TTL refreshed on use); DELETE forwards and then removes mapping. No business-data cache and no automatic replay of mutating requests. Redirects are not followed, and Location/Set-Cookie are not exposed. No credentials in URL configuration. Sessions are lost on restart; use sticky routing if multiple workers. Long-lived SSE can outlive session TTL, and expired session metadata is removed lazily on lookup. Opaque SSE event IDs are not rewritten: resume requests are forwarded to the upstream, which owns event retention and replay correctness.

This is a **transparent transport relay**, not an MCP SDK client/server or a managed browser-session bridge: it does not initialize, negotiate, validate JSON-RPC, guarantee upstream capabilities, synthesize sessions for stateless upstreams, or enforce cross-user authentication. Browser clients must implement MCP transport/session handling and protect their opaque tokens. CORS preflight is not implemented; serve from the same origin or add trusted reverse-proxy CORS handling. Node fetch may transparently decompress encoded upstream responses; it requests identity and drops content-encoding rather than promise literal wire-level byte identity. Only local fixture backends are used by tests.
